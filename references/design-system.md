# Board design system

一套用于「组件架构 / 能力视图」画板的视觉规则。目标：远看有重点，近看有信息，
导入飞书后仍然清晰可编辑。所有数值都对应 `scripts/boardkit.py` 的实现。

## 1. 画布与节奏

| 项 | 值 |
| --- | --- |
| 画板尺寸 | 宽 2100，高约 1200–2600（竖版更适合文档内嵌） |
| 外边距 | 左右 100，内容右边界 1964 |
| 区块间距 | 40–60；跨区箭头 46–80 |
| 卡片间距 | 68（双列）/ 40（三列） |
| 标注箭头间隙 | 100（左右各留 100 给标签文字） |
| 圆角 | 容器 3%，卡片 5%，胶囊 50%；圆角值是短边的百分比 |
| 描边 | 卡片 2px，容器 1.5px，箭头 2.6–3px；不用投影 |

尺寸公式：`区块高 = 96（标题带）+ 卡片高 + 22（内边距）`。

## 2. 纵向故事线

固定四段，自上而下：

1. **标题带**：小号 eyebrow + 56px 主标题 + 21px 一句话价值 + 右上角范围徽标。
2. **价值标签行**：3–5 个胶囊，每个 4–8 字，颜色与下方分区呼应。
3. **编号分区**：`01 / 02 / 03` 三个语义层（入口 → 平台 → 执行），
   每区一个浅色容器 + 编号徽标 + 标题 + 副标题 + 右上角补充说明。
4. **页脚**：左「设计愿景」，右「图例 / 颜色语义」。

缺省时宁可少一个分区，也不要四五个等权区块并排——等权等于没有重点。

## 3. 字阶（2100 宽画布）

| 用途 | 字号 | 字重 | 颜色 |
| --- | --- | --- | --- |
| 主标题 | 56 | 700 | `#0A1B33` |
| 副标题 / 价值句 | 21 | 400 | `#465A75` |
| 分区标题 | 28 | 700 | `#0A1B33` |
| 分区副标题 | 16 | 400 | `#64748B` |
| 卡片标题 | 22–24 | 700 | `#0A1B33` |
| 卡片副标题 | 15 | 400 | 强调色的深色版 |
| 正文 / 条目 | 15 | 400 | `#41546E` |
| 箭头标签 | 13 | 700 | 箭头颜色 |
| 元信息 / 图例 | 13–14 | 400 | `#8A99AD` |

底线：正文不小于 13。13px 之下导入飞书后基本不可读，`lint_board.py` 会拦。

## 4. 颜色

主色只承担「分类」，不承担装饰。

| 语义 | 主色 | 浅底 | 描边 | 适用 |
| --- | --- | --- | --- | --- |
| 入口 / 路由 | `#2563EB` | `#EFF5FF` | `#C7DAF4` | 统一入口、Gateway |
| 经典 / 兼容路径 | `#0D9488` | `#F0FAF8` | `#B9E3DC` | 命令入口 |
| 技能 / 能力 | `#059669` | `#F5FCF8` | `#BFE2CE` | SkillStore |
| 知识 / 数据 | `#7C3AED` | `#FAF8FF` | `#D8CBF5` | Mana、PostgreSQL |
| 执行 / 鉴权 | `#B45309` | `#FFFCF6` | `#EBCF9F` | Engine、CI/CD |
| 资源 / 中性 | `#475569` | `#F6F8FB` | `#CBD5E1` | 计算资源 |

- **60/30/10**：60% 白与浅灰底，30% 分区浅色，10% 饱和色（编号徽标、箭头、图标）。
- **一个深色块**：整张图只允许一块深色（如 `#0F2F6B` 的核心 Runtime），
  它是视觉锚点；出现第二块深色，重点立刻消失。
- 同一张图里最多 4 个主色；多出来的用中性灰。
- 浅色底只用于「容器 / 图标圆 / 胶囊」，大白卡片保持白底 + 彩色 2px 描边。

## 5. 卡片解剖

```
┌─────────────────────────────────────────────┐
│  (icon)  标题 24                             │
│          副标题 15（强调色深色版）            │
│                                             │
│  条目 15 ── 动词开头，一行说完                │
│  条目 15                                    │
│  条目 15                     [ 底部胶囊 13 ] │
└─────────────────────────────────────────────┘
```

- 图标圆：直径 50，位于 `(x+28, y+26)`；单字图标（言 / 令 / 知 / 执 / 发 / 算）比
  emoji 稳定，导入后不会变彩。
- 标题 `x+96`，副标题紧跟其下；条目从 `y+100` 起，行距 30。
- 底部胶囊放「去向 / 属性」：`Gateway → 用户 Agent Runtime`、`控制平面统一读写`。
  含 `→` 时渲染成胶囊，否则渲染成右下角小字。
- 一张卡最多 4 条、每条 ≤ 18 字；超出就拆卡，不要缩字号。

## 6. 箭头系统

| 形态 | 含义 |
| --- | --- |
| 实线 3px | 主路径 / 调用 |
| 虚线 3px | 可选、异步、规划中 |
| 双箭头 | 双向读写（知识、数据） |
| 灰色细线 | 弱关联，不承载叙事 |

- 标签放在箭头**中段上方**，13px 加粗，颜色跟随箭头；不要压在线上。
- 横向箭头两侧至少 100 的间隙，标签才不会挤到卡片。
- 跨区箭头保持同一条 x，形成中轴线（入口 → 平台 → 执行）。
- 每条箭头都是一个动词短语：`检索上下文`、`加载技能`、`受控任务`。

## 7. 三种布局配方

**A. 分层带（默认，适合平台类）**
标题 → `01 入口` → Gateway 横带 → `02 平台`（左右能力 + 中央核心）→ `03 执行` → 页脚。

**B. 中心辐射（适合单一中枢）**
中央放深色核心块，四周 4–6 张能力卡，箭头从核心指向能力；页脚放图例。
适合「一个内核 + 多个插件」。

**C. 泳道流水线（适合端到端流程）**
横向 4–6 列（人 → 接入 → 决策 → 执行 → 资源），列头为编号色块，卡片纵向堆叠。
只在「时序」比「职责」更重要时使用；否则会重蹈「流程图化、组件被缩化」的覆辙。

## 8. 让图「醒目」的六个开关

1. 主标题足够大（56），并且只留一句话副标题。
2. 编号徽标用饱和色，形成 01/02/03 的节奏。
3. 只有一块深色核心，其余保持浅色。
4. 每张卡一个图标、一个动词副标题、3 条以内要点。
5. 箭头加粗并带颜色标签，而不是一根灰线。
6. 底部图例解释颜色语义，让读者不用猜。

## 9. 常见失败模式

- 把图画成时序图：每个节点写 6 行步骤，组件的职责反而消失。
- 所有卡片等高同色，读者找不到主线。
- 文字 12px 以下、卡片塞满句子，导入后糊成一片。
- 箭头 1px 灰色，且没有标签。
- 深浅两套强调色同时出现，重心分裂。
- 背景使用大色块，导致文档里整页发灰。

- [ ] 每个色只对应一种语义？深色块只有一块？
- [ ] 所有正文 ≥ 13px，`lint_board.py` 无告警？
- [ ] 每条箭头都有动词标签，且标签没有压线？
